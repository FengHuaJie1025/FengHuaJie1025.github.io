## 引言：AI 热词层出不穷

这两年 AI 圈的热词层出不穷：LLM、Token、Prompt、RAG、MCP、Agent、Skill……光是念一遍就让人头大。这些词是怎么出现的？各自解决什么问题？今天用一个故事讲明白。

假设你这周末想到杭州玩——

## 一、大语言模型（LLM）与 Token

你打开对话窗口，随口问一句，AI 很快给了一段答复。这背后的核心就是大语言模型（LLM）。

LLM 将你的话拆解为 Token——它不是一个字，也不完全等于一个词，只是大模型理解文字的最小单元。每个 Token 对应着一个数字，叫 Token ID。大模型通过计算，预测出一个 Token 后面最该接哪一个，从而拼凑出完整回答。

## 二、提示词（Prompt）与提示词工程

在这个过程中，你的提问就是 Prompt（提示词）。不过你随口一问，AI 回答很浅显；换一种问法：

> "预算 2000，帮我按天规划行程"

回答立刻好用很多。这套把话说清楚的方法论就叫 Prompt Engineering（提示词工程）。

## 三、上下文（Context）

规划旅行不可能一句话说完。你限定预算 2000 后又补充："不想去网红景点"，AI 都能调整推荐方向。它是怎么记住的？

因为每次发消息时，系统会把之前的对话一起打包发给大模型，这就是 Context，也就是我们常说的上下文。

## 四、记忆（Memory）

但大模型理解上下文的长度是有限的。随着对话不断积累，模型会忘记最开始的内容。一个常见的做法是：让模型把之前的对话做一次压缩总结，只保留关键信息。这个被压缩过的关键信息就是 Memory（模型的记忆）。

到这里，模型已经越来越接近我们想象中智能的样子了。

## 五、RAG（检索增强生成）

对话继续。你接着问："看看我之前收藏的旅行攻略，规划行程啊"——哦，模型宕机了，它不知道你收藏的攻略是什么。

这时候就需要 RAG（Retrieval-Augmented Generation，检索增强生成）。它能读取你的私有资料，让回答更加真实可靠。流程如下：

1. 先把你的资料切成小片段，存进知识库
2. 当你提问时，系统检索出最相关的片段
3. 将这些片段作为背景资料，与你的问题拼接给模型
4. 模型阅读这段增强后的上下文，生成准确的回复

我们现在接触到的 AI 客服、AI 问答助手，背后都在用 RAG 技术。但归根结底，它也只是让模型答得更好。

## 六、Function Calling（函数调用）

大模型还不能真正干活。你说："帮我查询一下高铁票"，AI 回复："你可以打开 12306"——它只会告诉你怎么做，但没法真的查询到高铁车次。

Function Calling（函数调用）登场了。它让大模型具备接入外部工具的能力。整个机制如下：

1. 程序先告诉模型有什么第三方工具可以用
2. 再把你的对话发过去
3. 当模型判断需要调用工具时，输出一段结构化的函数调用指令
4. 程序拿到指令去查询车次
5. 把结果返还给模型
6. 模型就可以回复符合行程规划的车票了

### Function Calling vs MCP

很多人会把 Function Calling 和 MCP 混淆，觉得不是同一个东西吗？其实差别可大了：

- **Function Calling**：让模型按照约定格式输出调用指令
- **MCP**：让所有工具都遵循同一种格式，方便被模型接入

## 七、MCP（模型上下文协议）

这里有个工程问题：每接入一个新工具，就需要单独写适配代码，不同应用之间这些工作完全无法复用。

于是有了 MCP（Model Context Protocol，模型上下文协议）。它让所有第三方工具的接口统一了——AI 程序只需要对接 MCP 这一个协议，就能调用所有使用同一接口的工具。

## 八、Agent（智能体）

AI 能接入不同工具了，但你还得一步步指挥它。能不能你就说一句：

> "帮我把杭州旅行安排好，剩下全交给你"

可以，这就是 Agent（智能体）。

一个 Agent 接到目标后，会自己思考该怎么做——整个过程它自己规划步骤、调用外部工具、记录每一步的结果。

诶，这不都是我们刚刚讲过的能力吗？对，Agent 就是在 LLM 的基础上，把这些能力打包成一个能独立干活的系统。大模型再聪明，也只会在文本框里一问一答；而 Agent 能实实在在帮你干活，而且持续学习思考，越干越聪明。

### 市面上的 Agent 产品

市面上的 AI 产品本质上都是 Agent，都有思考规划的能力，只是形态不同、能自主执行的程度不同：

- **对话窗口**
- **编程 CLI 工具**
- **桌面助手**

像 OpenClaw 这种桌面助手为什么会爆火？因为它自主执行的能力上了一个台阶——不仅能操作你的本地电脑、定时执行任务，还能通过社交软件和你沟通，像一个真正帮你干活的助手。

## 九、Skill（技能）

理想情况下，Agent 能完全自己安排旅行，但实际上你还是得提醒它应该怎么干——提醒它按天规划行程、找本地攻略、查高铁信息。

那么 Skill（技能）来帮你了。你可以把所有的偏好和规则写进一个 Skill，下次 Agent 接到类似任务时，会参考这份文件，按规定办事。

### Skill 与 Prompt 的区别

有人说，这不就是 Prompt？是也不全是：

- **Prompt**：一次性的话术，像便签纸，每次用都得写
- **Skill**：可以重复使用的、程序化的能力，像一本书——有标题、有内容，随时可以翻看

Skill 本身就是结构化的。可以将你所有的 Skill 整合在一起，通过渐进式的披露机制在运行过程中按需激活读取，使用不同的 Skill，大大节省上下文和 Token，让任务执行的成本更低。

## 十、Harness（约束框架）

到这里，Agent 基本上已经接管了你的电脑。但能力越大，闯祸能力也越大。Agent 真的有时候会失控——比如你让它买车票，它买错了，甚至直接付钱。

那么 Harness 出现了。就像字面意思的"马具"一样，套上脱缰的 Agent，约束它的失控行为。

### Harness 的核心功能

1. **提供最全面的上下文**给模型，避免其失忆
2. **划定边界**，明确哪些红线坚决不能碰
3. **自动验收任务成果**，第一时间给出反馈，并引导修复

它的核心就是构造一个 AI 友好工作环境，确保在可控的范围内爆发生产力。毕竟谁也不想一觉醒来，Agent 把你的电脑格式化了。

## 结语：从聊天到干活

回到最初，你只是和 AI 说了一句"想去杭州玩"。但随着问题和需求的增多，AI 一层一层地加上了各种能力。

这些概念不是凭空冒出的黑话，每一个都是因为上一步遇到的具体问题，才出现的解决方案。今天讲的是 AI 怎么从聊聊天变成真的能干活这条主线。
